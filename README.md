# Планировщик задач (go_final_project)

Дипломный проект курса Go-разработчик — веб-сервер, реализующий REST API
планировщика задач (аналог TODO-листа) с фронтендом на HTML/CSS/JS.
Задачи хранятся в SQLite, могут быть одноразовыми или повторяться по
правилу (ежедневно с интервалом, еженедельно, ежемесячно, ежегодно);
при выполнении периодической задачи она автоматически переносится на
следующую дату по правилу, одноразовая — удаляется.

## Реализованный функционал

Обязательная часть задания выполнена полностью:

* веб-сервер и раздача фронтенда (`web`);
* создание и инициализация БД SQLite (`scheduler.db`);
* вычисление следующей даты выполнения задачи (`NextDate`);
* добавление, получение списка, получение по id, редактирование,
  удаление и отметка о выполнении задачи (`/api/task`, `/api/tasks`,
  `/api/task/done`).

### Задания со звёздочкой

Выполнены все дополнительные задания:

* переопределение порта веб-сервера через переменную окружения `TODO_PORT`;
* переопределение пути к файлу БД через переменную окружения `TODO_DBFILE`;
* полная поддержка правил повторения `w <дни недели>` и
  `m <дни месяца> [месяцы]` (включая `-1`/`-2` — последний/предпоследний
  день месяца) в функции `NextDate`;
* поиск задач по подстроке (в заголовке или комментарии) и по конкретной
  дате через параметр `search` у `/api/tasks`;
* аутентификация по паролю: `/api/signin` выдаёт JWT-токен, остальные
  API-запросы защищены middleware и требуют валидную куку `token`,
  если задана переменная окружения `TODO_PASSWORD`;
* Dockerfile для сборки и запуска сервера в контейнере.

## Запуск локально

Требуется Go 1.25+.

```bash
go run main.go
```

По умолчанию сервер слушает порт `7540` и создаёт файл БД
`scheduler.db` в текущей директории. Откройте в браузере
`http://localhost:7540/`.

Поведение можно настроить переменными окружения (все опциональны):

| Переменная      | Назначение                                             | По умолчанию      |
|-----------------|---------------------------------------------------------|--------------------|
| `TODO_PORT`     | порт веб-сервера                                        | `7540`             |
| `TODO_DBFILE`   | путь к файлу БД SQLite                                   | `scheduler.db`     |
| `TODO_PASSWORD` | пароль для входа; если не задан — аутентификация отключена | не задан (выключена) |

Пример запуска с переменными окружения:

```bash
TODO_PORT=7000 TODO_DBFILE=/tmp/scheduler.db TODO_PASSWORD=12345 go run main.go
```

Если `TODO_PASSWORD` задан, при открытии `http://localhost:<порт>/`
фронтенд перенаправит на страницу `login.html` — там нужно ввести
пароль, указанный в `TODO_PASSWORD`.

## Запуск тестов

Тесты лежат в директории `tests` и проверяют API запущенного сервера,
поэтому перед запуском тестов сервер должен быть запущен (см. выше).

```bash
go test ./tests
```

Настройки тестов — в файле [`tests/settings.go`](tests/settings.go):

* `Port` — порт, на котором тесты ожидают сервер (должен совпадать с `TODO_PORT`, если он задан);
* `DBFile` — путь к файлу БД относительно директории `tests` (по умолчанию `../scheduler.db`);
* `FullNextDate = true` — включает проверку правил `w` и `m` в `TestNextDate`;
* `Search = true` — включает проверку поиска в `TestTasks`;
* `Token` — уже заполнен рабочим JWT-токеном для проверки аутентификации.
  Чтобы он сработал, запустите сервер с `TODO_PASSWORD=todoTest2026`
  (именно этот пароль использовался при генерации токена):

  ```bash
  TODO_PASSWORD=todoTest2026 go run main.go
  ```

  Токен выдан со сроком действия 30 дней; если он всё же истёк, получите
  новый и замените значение `Token` в `tests/settings.go`:

  ```bash
  curl -X POST http://localhost:7540/api/signin \
    -H "Content-Type: application/json" \
    -d '{"password":"todoTest2026"}'
  ```

  Значение поля `token` из ответа и есть новый `Token`. Если запустить
  сервер без `TODO_PASSWORD`, аутентификация отключается и значение
  `Token` попросту игнорируется — тесты проходят как обычно.

## Запуск через Docker

Сборка образа:

```bash
docker build -t go-final-project .
```

Запуск контейнера с БД, сохраняемой на хосте, и (опционально) паролем:

```bash
mkdir -p ./data
docker run -d --name go-final-project \
  -p 7540:7540 \
  -v "$(pwd)/data:/app/data" \
  -e TODO_PASSWORD=12345 \
  go-final-project
```

После запуска планировщик доступен в браузере по адресу
`http://localhost:7540/`, а файл базы данных появится в `./data/scheduler.db`
на хосте (путь внутри контейнера — `/app/data/scheduler.db`, задан через
`TODO_DBFILE` в `Dockerfile`). Переменную `TODO_PASSWORD` можно не
указывать — тогда аутентификация будет отключена.
